# Devin session report (daily / weekly / monthly)

Produce a report of the requesting user's Devin sessions grouped by project (repository) then session, for one window: a day, a Mon–Sun week, or a calendar month. The report is for <NAME> (user id `<USER_ID>`, organization `<ORG_ID>`, timezone `<TZ>`, Devin API `<API_BASE>` e.g. `https://api.devin.ai/v3` or `https://<host>.devinenterprise.com/api/v3`, session URLs `<SESSION_URL_PREFIX>`) unless the prompt says otherwise. Every `<…>` placeholder in this file (here and in steps 1, 4 and 6) must be replaced when installing it (README.md → Recipes); a `<` left behind means an unfilled value. The tooling lives in the repository `Open-MBEE/devin-automation` (`README.md` there explains the numbers and their caveats).

## Procedure

1. Work out the window from the prompt (kind = `daily` | `weekly` | `monthly`; `--start` = first day, `--end` = the day AFTER the last day, both `YYYY-MM-DD` in the user's timezone). Convert both to unix seconds at local midnight:
   `python3 -c "import datetime as dt; from zoneinfo import ZoneInfo; TZ=ZoneInfo('<TZ>'); print(int(dt.datetime(Y,M,D,tzinfo=TZ).timestamp()))"`.
2. Get the tool: `git clone https://github.com/Open-MBEE/devin-automation ~/repos/devin-automation` (or `git -C ~/repos/devin-automation pull`), then `mkdir -p ~/bin && curl -fsSL https://github.com/Open-MBEE/devin-automation/releases/latest/download/session-report-linux-x86_64 -o ~/bin/session-report && chmod +x ~/bin/session-report && ~/bin/session-report --version`. If the download fails (no release yet), fall back to `cd ~/repos/devin-automation && lake build` (~10 minutes; start it in the background now so it overlaps with the collection) and use `.lake/build/bin/session-report`.
3. Collect: `session-report collect --start <start> --end <end> --tz <TZ> --user <USER_ID> --org <ORG_ID> --out ~/report/raw.json` (reads `DEVIN_API_KEY` from the environment; set `DEVIN_API_BASE=<API_BASE>` if it is not `https://api.devin.ai/v3`). It pages the Devin REST API; a week takes a few minutes, a month longer. It exits non-zero if the session search was cut short — report that, do not proceed.
4. Build: `session-report build --kind <kind> --start <start> --end <end> --raw ~/report/raw.json --out ~/report --who "<NAME>" --tz <TZ> --base-url <SESSION_URL_PREFIX> [--owners <GitHub owners whose owner/repo mentions in a prompt count as the project>]` → `~/report/devin-report-<slug>.md`, `~/report/report-<slug>.json`, `~/report/tables-<slug>.json`, `~/report/yaml/<slug>/*.yaml`. Then `session-report check ~/report/yaml/<slug>/*.yaml` must print `ok` for all five (a FAIL means the data does not fit the schema — report it, do not hand-edit) and `cd ~/report/yaml && zip -r ../devin-report-<slug>-yaml.zip <slug>`.
5. HTML: invoke the `devin-artifact` skill, then `html_artifact_compile` with `body_path=~/repos/devin-automation/session-report/body.html`, `data_path=~/report/report-<slug>.json`, `output_path=~/report/devin-report-<slug>.html`, `screenshot=false`.
6. Publish: `cd ~/repos/devin-automation && git checkout -b report/<slug> main && scripts/stage-report.sh <slug> ~/report` (copies the Markdown, the HTML and the five YAML tables to `reports/<slug>/` under their canonical names), commit (`report: <kind> <slug>`), push the branch and open a PR against `main` with the git tools; its body is the summary of step 7. Do not merge: merging is the user's decision, and it is what updates the report index on GitHub Pages. If the window had no sessions, open no PR.
7. Deliver with `message_user`, attaching the `.html`, the `.md` and the YAML zip (pin them), with the PR link and a 3–5 line summary: sessions, projects, working time, PRs opened, the top 3 projects by working time, and the standing caveats (ACUs are session-lifetime totals: † = created before the window, ‡ = created in it but still active after it, so only unmarked sessions' ACUs belong to the window alone; working time is the status-working proxy for VM time; the API exposes no VM size). Do not restate the tables in the message.

Never quote a dollar figure: ACUs only (the per-ACU rate is in the account's contract). Never push to `main` and never merge; the only write to the repository is the `report/<slug>` branch and its PR.
