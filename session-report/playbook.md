# Devin session report (daily / weekly / monthly)

Produce a report of the requesting user's Devin sessions grouped by project (repository) then session, for one window: a day, a Mon–Sun week, or a calendar month. The report is for Nicolas Rouquette (user id `user-949478cfacab4d699a4535f534afaf70`, timezone `America/Los_Angeles`, session URLs `https://nasa-jpl-demo.devinenterprise.com/sessions/`) unless the prompt says otherwise. The tooling lives in the repository `Open-MBEE/devin-automation` (`README.md` there explains the numbers and their caveats).

## Procedure

1. Work out the window from the prompt (kind = `daily` | `weekly` | `monthly`; `--start` = first day, `--end` = the day AFTER the last day, both `YYYY-MM-DD` in the user's timezone). Convert both to unix seconds at local midnight:
   `python3 -c "import datetime as dt; from zoneinfo import ZoneInfo; TZ=ZoneInfo('America/Los_Angeles'); print(int(dt.datetime(Y,M,D,tzinfo=TZ).timestamp()))"`.
2. Get the tool: `git clone https://github.com/Open-MBEE/devin-automation ~/repos/devin-automation` (or `git -C ~/repos/devin-automation pull`), then `mkdir -p ~/bin && curl -fsSL https://github.com/Open-MBEE/devin-automation/releases/latest/download/session-report-linux-x86_64 -o ~/bin/session-report && chmod +x ~/bin/session-report && ~/bin/session-report --version`. If the download fails (no release yet), fall back to `cd ~/repos/devin-automation && lake build` (~10 minutes; start it in the background now so it overlaps with the collection) and use `.lake/build/bin/session-report`.
3. Collect: read `~/repos/devin-automation/session-report/collect.py`, replace `__START__`, `__END__` with the unix seconds, `__USER__` with the user id, `__TZ__` with the timezone and `__OUT__` with `/home/ubuntu/report/raw.json`, and run the result as the `script` of the `scripted_tools` tool with `timeout_secs` 7200 (it pages the Devin session-search and session-events tools: a week takes ~3 minutes, a month ~5). The script body must be inline — do not `exec(open(...))` it.
4. Build: `session-report build --kind <kind> --start <start> --end <end> --raw ~/report/raw.json --out ~/report --who "<name>" --tz <tz> --base-url <session URL prefix> --owners Open-MBEE,nasa-jpl` → `~/report/devin-report-<slug>.md`, `~/report/report-<slug>.json`, `~/report/tables-<slug>.json`, `~/report/yaml/<slug>/*.yaml`. Then `session-report check ~/report/yaml/<slug>/*.yaml` must print `ok` for all five (a FAIL means the data does not fit the schema — report it, do not hand-edit) and `cd ~/report/yaml && zip -r ../devin-report-<slug>-yaml.zip <slug>`.
5. HTML: invoke the `devin-artifact` skill, then `html_artifact_compile` with `body_path=~/repos/devin-automation/session-report/body.html`, `data_path=~/report/report-<slug>.json`, `output_path=~/report/devin-report-<slug>.html`, `screenshot=false`.
6. Deliver with `message_user`, attaching the `.html`, the `.md` and the YAML zip (pin them), with a 3–5 line summary: sessions, projects, working time, PRs opened, the top 3 projects by working time, and the standing caveats (ACUs are session-lifetime totals: † = created before the window, ‡ = created in it but still active after it, so only unmarked sessions' ACUs belong to the window alone; working time is the status-working proxy for VM time; the API exposes no VM size). Do not restate the tables in the message.

Never quote a dollar figure: ACUs only (the per-ACU rate is in the account's contract). Do not write to the repository.
